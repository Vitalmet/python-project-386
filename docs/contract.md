# API-контракт «Календарь звонков»

Контракт зафиксирован в TypeSpec (`typespec/`) и скомпилирован в OpenAPI-спецификацию
(`openapi/openapi.yaml`). Контракт — источник истины для эндпоинтов приложения.

## Как пересобрать спецификацию

```bash
cd typespec
npm install
npx tsp compile .
```

## Покрытие сценариев

### Сценарий гостя

| Шаг | Сценарий | Операция OpenAPI | Статус |
|-----|----------|------------------|--------|
| 1 | Гость видит виды брони: название, описание, длительность | `GET /event-types` | OK |
| 2 | Гость открывает тип события | `GET /event-types/{eventTypeId}` | OK |
| 3 | Гость смотрит свободные слоты на 14 дней | `GET /event-types/{eventTypeId}/slots?from&to` | OK |
| 4 | Гость создаёт бронирование на свободный слот | `POST /bookings` | OK |
| 5 | Система отклоняет бронь на занятый слот | `POST /bookings` → `409 SLOT_BUSY` | OK |
| 6 | Гость видит подтверждение брони | `GET /bookings/{bookingId}` | OK |

### Сценарий владельца

| Шаг | Сценарий | Операция OpenAPI | Статус |
|-----|----------|------------------|--------|
| 1 | Владелец видит типы событий | `GET /admin/event-types` | OK |
| 2 | Владелец создаёт тип события | `POST /admin/event-types` | OK |
| 3 | Владелец видит предстоящие встречи всех типов | `GET /admin/bookings/upcoming` | OK |

### Ограничения, отражённые в контракте

- уникальность имени типа события и `durationMinutes >= 1` — `EventTypeCreate`;
- правило занятости (нет двух броней на одно время, даже разных типов) — ответ
  `409 SLOT_BUSY` у `POST /bookings`;
- окно бронирования 14 дней — опциональные параметры `from`/`to` у
  `GET /event-types/{eventTypeId}/slots`;
- слот `Slot` содержит `start`, `end` (start + длительность), `available`;
- владелец — единый предзаданный профиль, в контракте нет эндпоинтов авторизации,
  админская часть доступна по префиксу `/admin`.
