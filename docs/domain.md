# Доменная модель: «Календарь звонков»

## Роли

### Владелец календаря
- Единственный предзаданный профиль. В системе нет регистрации и авторизации.
- Профиль владельца «по умолчанию» используется в админской части приложения.
- Может создавать типы событий и просматривать страницу предстоящих встреч.

### Гость
- Бронирует слоты без создания аккаунта и без входа в систему.
- Видит виды брони, выбирает тип события, свободный слот и создаёт бронирование.

## Сущности

### Владелец (Owner)
Предзаданный профиль, используемый админской частью. Хранится как константа
конфигурации (имя, контактные данные), CRUD для него отсутствует. Авторизация не требуется.

### Тип события (EventType)
Тип встречи, который владелец может предложить гостям.

| Поле             | Тип     | Ограничения                     |
|------------------|---------|---------------------------------|
| `id`             | int     | первичный ключ                  |
| `name`           | string  | уникальное, обязательное        |
| `description`    | string  | обязательное                    |
| `durationMinutes`| int     | > 0, длительность события       |

### Слот (Slot)
Доступный временной интервал для бронирования в окне 14 дней.
Не хранится в БД — вычисляется сервисом доступности.

| Поле      | Тип     | Описание                                  |
|-----------|---------|-------------------------------------------|
| `start`   | datetime| начало слота (ISO 8601)                   |
| `end`     | datetime| конец = `start + durationMinutes` типа    |
| `available`| bool   | свободен ли слот                          |

Правила формирования слотов:
- окно бронирования: 14 дней начиная с текущей даты;
- доступные часы: будни 09:00–18:00, шаг сетки 30 минут;
- сегодня доступны только слоты, которые ещё не начались;
- слот свободен, если интервал `[start, end)` не пересекается ни с одним
  существующим бронированием (любого типа события).

### Бронирование (Booking)
Запись гостя на конкретный слот типа события.

| Поле           | Тип     | Ограничения                              |
|----------------|---------|------------------------------------------|
| `id`           | int     | первичный ключ                           |
| `eventTypeId`  | int     | FK на тип события                        |
| `guestName`    | string  | обязательное                             |
| `phone`        | string? | опционально, для связи                   |
| `email`        | string? | опционально, для связи                   |
| `startsAt`     | datetime| начало бронирования (ISO 8601)           |
| `createdAt`    | datetime| дата создания                            |

Правило занятости: на одно и то же время нельзя создать две записи, даже если
это разные типы событий. Конец бронирования = `startsAt + durationMinutes`.

## Публичный сценарий гостя

1. Гость открывает страницу видов брони — видит список типов событий
   (`name`, `description`, `durationMinutes`).
2. Гость выбирает тип события — открывается календарь со свободными слотами
   на ближайшие 14 дней.
3. Гость выбирает свободный слот.
4. Гость вводит имя (обязательно) и, при желании, телефон или email.
5. Система создаёт бронирование, если слот по-прежнему свободен, иначе возвращает
   ошибку занятости.
6. Гость видит подтверждение бронирования (дата, время, тип события).

## Сценарий владельца

1. Владелец создаёт тип события (id, название, описание, длительность в минутах).
2. Владелец открывает страницу предстоящих встреч — единый список бронирований
   всех типов событий, отсортированный по времени, только будущие встречи.
